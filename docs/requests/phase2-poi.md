## 変更内容(タスクごとに1コミット。各コミット前に npm test と npm run build が緑)

### T1. Overpass取得の統合とアクセス制限対策
- 峠・山(既存)と補給・休憩(新規)を **1回のOverpassリクエスト** で取得する(公開サーバーのIP単位レート制限に実際にかかったため)。
  `src/osm.ts` にクエリ生成・応答の振り分けを置き、`places.ts` は振り分け済みの峠データを既存の `filterPlaces` で処理する形にする。
  峠・山の判定条件・半径・キャッシュ・2度制限などの既存仕様は維持(既存テストを緑のまま)。
- 補給・休憩は route の bbox ではなく、ルート線に沿った `around` フィルタで取得する:
  ルートを Douglas-Peucker で簡略化(許容誤差 30m、最大400点。超える場合は許容誤差を倍々に上げる)し、
  `nwr(around:<半径>,lat1,lng1,lat2,lng2,...)[条件]` を種類ごとに並べる。way/relation は `out center` で代表点を得る。
  半径は種類ごとの最大値で取得し、最終的な距離判定はクライアント側で既存の `nearestOnRoute` を使って種類ごとに行う。
- 応答が HTTP 429 / 504、または本文に `rate_limited` / `timeout` を含む場合は「Overpassが混雑中」としてステータス(warn)に出し、
  30秒後に1回だけ自動再試行する。失敗はキャッシュしない。それ以外の失敗は既存どおり省略して通知。
- `osm.ts` の純関数(簡略化、クエリ生成、応答の振り分け、レート制限判定)にユニットテスト。

### T2. 補給・休憩の判定・一覧・地図
- 種類と条件(`src/config.ts` の `poi` に定義。キー・ラベル・色トークン・既定表示・判定半径):
  | key | 表示名 | OSM条件 | 既定表示 | 半径 |
  |---|---|---|---|---|
  | conv | コンビニ | shop=convenience | ON | 300m |
  | shop | 商店 | shop=supermarket / general / grocery / greengrocer / bakery / deli | ON | 300m |
  | vend | 自販機 | amenity=vending_machine かつ(vending タグなし、または vending に drinks を含む) | ON | 100m |
  | water | 水場 | amenity=drinking_water、man_made=water_tap かつ drinking_water=yes、natural=spring かつ drinking_water=yes | ON | 200m |
  | wc | トイレ | amenity=toilets | OFF | 200m |
  | michi | 道の駅 | name が「道の駅」で始まる(タグ種別は問わない)。highway=rest_area/services で name に「道の駅」を含むものも | ON | 500m |
  1地物が複数条件に当たる場合は表の上の種類を優先(道の駅だけは最優先)。
- 名称: `name:ja` → `name` → `brand` → 種類の表示名。営業時間: `opening_hours` があれば表示(`24/7` は「24時間」)。
- 自販機は、ルート上の距離で200m以内に連続するものを1行にまとめる(「自販機 3台」)。地図の印も代表点1つ。
- `src/poi.ts` の純関数: 種類判定、ルート上距離での並べ替え、自販機のまとめ、**補給なし最長区間**の計算。
  補給なし区間は「コンビニ・商店・道の駅」を補給点とし、始点・終点を含めた最長の空白区間 {from, to}(m)を返す。
  チップの表示ON/OFFには左右されない(データ上の事実として計算する)。警告の閾値は `config.poi.gapWarnKm = 20`。
- UI(モック準拠):「通過する峠・山」の次に「補給・休憩」セクション。
  - 種類チップ(aria-pressed、件数つき。自販機の件数は台数)。表示ON/OFFは localStorage に保存(try/catch)。
  - 補給なし最長区間の注意(閾値以上は `.gap-note`、未満は `.gap-note.ok`)。
  - 一覧: アイコン / 名称 / 「ルートから◯m · 営業時間」/ 右に「◯km」。最初の30行を表示し、残りは「さらに表示」。行タップで地図をその地点へ移動してポップアップを開く。
  - 状態表示: 検索中・0件・失敗・混雑中は既存の峠セクションと同じ `.empty` で表示。
  - 地図: `.poi-marker`(種類色+白アイコン、ズーム13未満は12pxの点)。経由点・峠ラベル・ルート線より下に描く。
    ポップアップに名称・種類・km地点・ルートからの距離・営業時間と「Googleマップで確認」リンク
    (`https://www.google.com/maps/search/?api=1&query=<lat>,<lng>`、新しいタブ、rel=noopener)。
  - スマホのボトムシートでも同じセクションを表示(既存のシート内スクロール)。

### T3. 標高グラフとGPX
- 標高グラフ: 補給なし最長区間が閾値以上なら、その区間を `--gap-bg` の帯で塗る(勾配の塗りより下)。
  表示中の補給・休憩を x軸のすぐ上に種類色の点(半径4、白縁)で描く。ホバーの吹き出しは既存どおり。
- **不具合修正: 峠・山の名前の重なり**。グラフ上の名前ラベルは、文字幅を見積もり(全角11px相当)、
  重なる場合は最大3段に段をずらし、それでも重なる場合はピーク(natural=peak)より峠を優先して表示し、
  表示しきれないものは▼だけ残す。ラベルはグラフの左右端からはみ出さない。純関数にしてユニットテスト。
- GPX: 「表示中の補給・休憩をGPXのウェイポイントに含める」チェック(既定ON、localStorage保存)。
  ONの場合、表示中の種類の地物を `<wpt>` で出力(`<name>`=名称、`<type>`=種類の表示名、`<sym>` は
  conv/shop=Convenience Store、vend/water=Drinking Water、wc=Restroom、michi=Restaurant)。峠・山の既存wptは維持。
  GPX読込時、type が補給・休憩の表示名のwptは峠・山として取り込まない(既存の往復テストを緑のまま、往復テストを追加)。

### T4. 既存不具合の修正(Google背景・ステータス)
- **Google背景のズーム不具合**: `nativeZoom` が viewport 応答の `maxZoomRects` の最小値を使っているため、
  全世界を覆う maxZoom 9 の矩形が含まれると、どのズームでも z9 のタイルを引き伸ばして地図が真っ白に見える
  (2026-10-10、京都・花脊峠付近の terrain で確認。同地点で z13〜18 のタイルは HTTP 200 で取得できた)。
  修正: 表示範囲の中心点を含む矩形の maxZoom の **最大値** を使う(中心を含む矩形がなければ全矩形の最大値)。
  ユニットテストを実際の応答形(全世界 maxZoom 19 と 9、地域ごとの 13〜20 が混在)で追加し、既存テストの期待値も修正。
- ステータス行のGoogle表示中メッセージを「Google背景を表示中」に短縮(出典の説明は帰属表示にあるため)。
