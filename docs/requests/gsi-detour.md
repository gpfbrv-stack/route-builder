## 変更内容(タスクごとに1コミット相当)

### T1. 途切れの橋渡し(`src/gsi-router.ts`)
- グラフ構築後に連結成分を求め、**異なる成分どうしの最も近い節点の組が 30m 以内** なら、その2点を結ぶ「橋」辺を追加する
  (重み = 距離 × 3。設定 `config.gsi.bridgeM = 30`, `config.gsi.bridgePenalty = 3`)。成分の組ごとに最大1本。
  計算量を抑えるため、節点を約30mの格子に分けて近傍だけを比較する(全組の総当たりはしない)。
- 経路が橋を使った場合、Segment に `bridged: true` を付ける(UIで使う)。
- テスト: 16m 離れた2成分が橋でつながる、31m 以上はつながらない、同一成分内には橋を作らない、橋は通常の道より割高(通常の道で行けるならそちらを選ぶ)、格子近傍探索の境界。

### T2. OSMの大回り検出と切り替え提案
- 'road' 区間で BRouter が成功したとき、区間の経路長 L と直線距離 D を比べ、**L > max(2.5×D, D + 1000m)** なら「大回り候補」とする
  (設定 `config.gsi.detourRatio = 2.5`, `config.gsi.detourExtraM = 1000`)。
- 大回り候補の区間について、バックグラウンドで地理院の道でも計算する(既存の GsiRouter。同時1区間、失敗は黙って無視)。
  地理院の経路長 Lg が **Lg < 0.6 × L** なら提案を出す。
- 提案UI: ステータス行(info)に「区間 n→n+1: 地理院の道なら ◯km(OSM ◯km)」と「切り替える」ボタン。
  複数ある場合は「◯区間で地理院の道の方が短く引けます」と「すべて切り替える」。押すとその区間の legMode を 'gsi' にする(Undo 1回で戻る)。
  経由点リストの該当区間にも小さな「地理院の方が短い」表示と同じ切り替えボタン。
  ユーザーが変更(切り替え・編集)したら提案は消える。同じ区間・同じ結果について、閉じた提案は再表示しない。
- 自動では切り替えない(OSMが大回りする理由が「通れない」場合もあるため)。
- テスト: 大回り判定の境界、提案が出る/出ない(Lg の比率)、切り替えで legMode='gsi' と Undo、編集で提案が消える、BRouter成功区間でのみ判定。
