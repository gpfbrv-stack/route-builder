# UI再設計の実装(ブランチ feature/ui-redesign)

## 目的
自転車用ルートビルダー(C:\Users\yuhei\route-builder、Vite + TypeScript + Leaflet 1.9、静的サイト)の画面を、
デザイナーが作成したモック `docs/design/mockup.html` のとおりに作り直す。
機能(ルーティング・標高・峠・GPX・自動保存・共有URL・Google背景)はすでに動いているので、それらを壊さずにUIだけを置き換え、
あわせて「ルート線のドラッグで経由点を挿入」を追加する。

## 正となる資料

  ボトムシートの挙動、標高グラフの描き方はモックから移植してよい(モックのJSはデモ用。データ処理は既存モジュールを使う)。
- モックの確認: `npm run dev` 起動中に http://127.0.0.1:5188/docs/design/mockup.html (PC幅とスマホ幅375px)。
- 既存仕様: `H_README.md`(設定と制限の節)。既存の挙動・制限値は変えない。

## 変更内容(タスクごとに1コミット。各コミット前に npm test と npm run build が緑であること)

  標高 / 通過する峠・山 / 経由点(折りたたみ) / 注記)+ 下部固定フッター(「GPXで保存」主ボタン、「共有」)。右に地図。
  スマホ(767px以下): 地図全面。上部に走り方セグメントと「…」メニュー(道に沿う / GPXを読み込む / 共有URLをコピー / ルートを全消去)。
  右側にレイヤー・現在地ボタン、シート上端に追従して元に戻す・全体表示ボタン。下部はボトムシート。
- CSSトークンはモックの `:root` をそのまま採用(DADSライト配色、角丸8px、8px単位、フォーカスは黒枠+黄)。

- `<meta name="theme-color" content="#ffffff">` 維持。titleは「ルートビルダー」。

### T2. 部品の移植と既存機能の配線
- 走り方: セグメントボタン(aria-pressed)。PCとスマホの2か所は同じ状態を共有。道に沿う: スイッチ(checkbox)。
- ルート名: サイドバー上部の大きな見出し風input(フォーカス時のみ枠)。スマホのシートpeek行には名前とGPXボタン。
- ステータス: 旧 notice / elevation-status / storage-status / map-status を、ドット付き1行のステータス
  (`.status` / `.status.busy` / `.status.warn`)に統合する。優先度: エラー・警告 > 計算中 > 完了情報。
  峠検索の状態(検索中・0件・失敗)は「通過する峠・山」セクション内に `.empty` として表示する。
  文言は既存のものを流用してよい(短くしてよい)。
- 数値カード: 距離(km、小数1桁)/ 登り / 下り / 最高点(m、3桁区切り)。計算中・未計算は「—」。
- 標高グラフ: モックと同じ描画(500m区間ごとの勾配で塗り分け、黒の標高線、100m刻みグリッド、5km刻みの距離目盛、
  峠・山の名前と▼、ホバー/タッチでクロスヘア+吹き出し「km · m · 勾配%」+地図上のカーソル点)。
  旧グラフの下のrangeスライダーは廃止し、代わりにSVGをフォーカス可能にして左右キーで位置を動かせるようにする(キーボード操作の代替)。
  勾配区間の計算は純関数 `src/grade.ts`(例: `gradeBins(samples, binM): {from,to,grade}[]`、欠測を含む区間はgrade=null→下り色ではなく塗らない)
  に切り出し、ユニットテストを付ける。勾配色の閾値は 3/6/9/12% と下り(負)。凡例を表示。
- 通過する峠・山: 行(▲アイコン / 名前 / 「◯km地点 · ルートから◯m」/ 標高)。タップで地図をその地点へ。
  地図上のラベルはモックの `.pass-label`(白地・黒枠・吹き出し)に置き換える(旧circleMarker+tooltipを廃止)。
- 経由点: 折りたたみ(details)。行は S / 番号 / G のバッジ、「スタート/経由点/ゴール」、「◯km · 標高◯m」(未計算時は「—」)、×削除ボタン。
  緯度経度の表示はやめる。地図マーカーもモックの `.wp-marker`(始点=success色「S」、終点=黒「G」、中間=番号)。
  マーカーをクリックした時の削除ポップアップは維持。
- ルート線: 白い縁取り(weight 11)+ 本線(--route、weight 6)の2本重ね。
- レイヤー選択: Leafletの L.control.layers を廃止し、モックの `.layer-pop`(サムネイル付き3列グリッド、地理院/その他/Google)に置き換える。
  Googleの3種はAPIキー設定時のみ表示(キー未設定ならGoogleグループごと非表示)。`google-layer.ts` の
  `addGoogleLayers` は L.Control.Layers に依存しない形(例: レイヤー一覧を返す)に変更し、帰属表示・ロゴ・失敗時の地理院へのフォールバック・
  セッション更新の挙動はそのまま維持する。選択中の背景は localStorage に保存して次回復元(try/catch)。
- 拡大縮小: Leafletのzoom controlは使わず、モックの `.fab-group` ボタン(PCのみ。スマホはピンチ)。縮尺はLeafletの scale control を左下に維持。
- 現在地ボタン: Geolocation APIで現在地へ移動し、青い点を表示(追従はしない)。拒否・失敗時はステータスに警告。
- PCの編集バー(地図下部中央): 元に戻す / 全体表示 / 全消去。ヒントチップ(地図上部中央)は経由点が2点未満の時だけ表示。
- スマホのボトムシート: 3段スナップ(168px / 画面高の50% / 88%)。つまみのタップで次の段、ドラッグで追従→最寄りの段へ。
  `--sheet-h` に追従して、地図右下のボタン・Leafletの左下(縮尺・Googleロゴ)・右下(帰属表示)が隠れないよう持ち上げる。
  「全体表示」はシートの高さを考慮した余白で fitBounds する。既存の panel.ts を置き換えてよい。
- GPX保存ボタンは計算完了まで disabled(既存の syncExport の条件を維持)。共有URLはクリップボードへコピーしてステータスで通知。
  コピー失敗時は読み取り専用inputをシート/サイドバー内に表示して選択状態にする(既存挙動)。
- 全消去はスマホのメニューとPCの編集バーで error色の文言にする。元に戻すで復元可能なので確認ダイアログは不要。

### T3. ルート線ドラッグで経由点を挿入
- ルート線(本線)をドラッグすると、その位置に新しい経由点を挿入し、離した位置へ移動する(Google マップ/一般的なルートプランナーと同じ操作)。
- どの経由点の間に入れるかは、ドラッグ開始点が属する区間(経由点i→i+1のルーティング結果)で決める。区間ごとの形状を保持して判定すること
  (経由点からの距離ではなく)。直線モードでも同様に動く。
- ドラッグ中は破線のプレビュー(前後の経由点と結ぶ直線)を出し、離した時に1回だけ change() する(Undo 1回で戻る)。
- 地図クリック(末尾追加)と競合しないこと。スマホでは長押し(約400ms)で開始し、通常のパン操作を妨げないこと。
- GPX読込で importedTrack を保持している間は挿入を無効にする(既存仕様: 編集すると再計算になるため、挿入も通常の編集として扱ってよい)。
- 区間判定ロジックは純関数にしてユニットテストを付ける(例: 区間形状の配列と点から、最も近い区間indexを返す)。
