# 編集体験の改善(ブランチ feature/editing-ux)

## 目的
自転車用ルートビルダー(C:\Users\yuhei\route-builder、Vite + TypeScript + Leaflet 1.9、静的サイト)の編集操作で、
ユーザーが不満を挙げた4点を直す。
1. 経由点を足すと、一度ルート全体が直線になってから道に沿った線に変わる(ちらつき)。
2. Google背景で地図を動かすたびに、一度真っ白になる。
3. 走り方(山サイ/グラベル/ロード)を切り替えると、既存ルート全体が引き直される。
4. ルートの途中をつかんで経由点を追加し、部分的に編集したい(既存のドラッグ挿入は見つけにくく、ドラッグ中は直線プレビューのみ)。

## 前提

- Google背景: `src/google-layer.ts`(movestart で `tiles.setOpacity(0)`、settle 後に viewport を取り直して必要ならタイル層を作り直す実装)。
- 見た目のトークン・部品は既存の `src/style.css` と `docs/design/mockup.html` に従う。

## 変更内容(タスクごとに1コミット。各コミット前に npm test と npm run build が緑)

### T1. Google背景のちらつき解消(項目2)
- 移動・ズーム中にGoogleタイルを透明にしない(`setOpacity(0)` をやめる)。
- タイル層の作り直しは、セッショントークンか maxNativeZoom が変わった時だけ。作り直す場合は新しい層を追加し、
  その `load` 後(または5秒のタイムアウト後)に古い層を外す(白抜けを出さない)。
- 帰属表示(copyright)の viewport 取得は従来どおり moveend 後のデバウンスで更新。表示ポリシー上、帰属表示は常に出しておく。
- テスト: 移動中に不透明度が変わらない、maxNativeZoom 不変ならタイル層を作り直さない、変わったら新層→load→旧層除去。

### T2. 区間ごとの走り方(項目3)
- 状態に区間ごとの走り方を持たせる(例: `legProfiles: Profile[]`、長さ = 経由点数−1)。
  「現在の走り方」(セグメントボタン)は **これから引く区間** にだけ適用し、切り替えても既存区間は再計算しない。
  切り替え時のステータス(info): 「これから引く区間を◯◯で計算します」。
- 区間の走り方の継承: 末尾追加=現在の走り方。ルート線への挿入で分割された2区間=元の区間の走り方。経由点の移動=その区間の走り方のまま。経由点削除で結合される区間=前側の区間の走り方。
- 引き直し操作: 経由点リストの各行(区間)に走り方の小さな表示(例「ロード」)と、地図の経由点ポップアップ/リストのメニューに
  「この区間を現在の走り方で引き直す」。「…」メニュー(スマホ)とPCの編集バーに「全区間を現在の走り方で引き直す」。どれもUndo 1回で戻る。
- 保存・共有: localStorage と共有URLに `legProfiles` を含める(共有URLは v2。v1 は全区間を v1 の profile として読み込む)。
  GPX読込は全区間を現在の走り方にする。FITの subSport は区間距離が最も長い走り方。
- ルーティングのキャッシュキーは「区間の走り方+区間座標」。区間の走り方が変わらなければ再要求しない。
- テスト: 切替で再要求が発生しない、各継承規則、引き直し(1区間/全区間)とUndo、v1/v2 の共有URL往復。

### T3. 描画のちらつき解消と、ドラッグ中のライブ経路(項目1・4)
- 経由点の追加・移動・挿入・削除で、**計算済みの区間の線はそのまま残し**、再計算が必要な区間だけを
  「破線の仮線」(--route 色、不透明度0.6、weight 4、dashArray '6 8'、前後の経由点を直線で結ぶ)で表示し、
  結果が届いた区間から実線に置き換える。全体を一度直線に戻す描画はしない。直線モードの区間は従来どおり実線の直線。
- ルート線の掴みやすさ: 本線の上に透明の当たり判定線(weight 24、pointer-events 有効)を重ねる。
  PCでホバー中は、カーソルに最も近いルート上の点に「挿入ハンドル」(直径14pxの白丸、--route色2px枠)を表示し、カーソルは grab。
  経由点マーカーの上ではハンドルを出さない。スマホは既存の長押し(約400ms)開始を維持。
- ドラッグ中のライブ経路: ドラッグ中(挿入・既存経由点の移動とも)、影響する前後2区間を、最後の要求から400ms以上空けて
  再計算し、届いた結果を表示する(古い要求は破棄。届くまでは破線の仮線)。ドロップ時に最終位置で確定し、change() は1回だけ(Undo 1回)。
  ライブ中の結果も区間キャッシュに入れてよいが、公開サーバー保護のため同時要求は既存の上限を超えない。
- 既存の地図クリック(末尾追加)、経由点ドラッグ、区間判定(route-segment)の挙動とテストは維持。
- テスト: 追加時に既存区間の線が直線化しない、仮線→実線の置換、ホバーハンドルの表示条件、ライブ要求の間引き(400ms)と破棄、
  ドロップで change 1回。
